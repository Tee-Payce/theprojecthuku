# Phase 1 External Setup Guide

This guide connects the Phase 1 authentication and project foundation to a real Supabase project.

The approved authentication method is **email and password**. SMS OTP and WhatsApp OTP are deferred and are not required for this setup.

Email confirmation uses the Expo callback route `auth/callback`. The exact callback URL depends on whether you are running a development build, Expo Go, or web.

## What You Need

- A Supabase account
- Access to the project workspace
- Node.js and npm installed
- A device, emulator, or Expo web target for testing
- The repository at `c:\personal\theprojecthuku`

The app currently uses:

- Supabase Auth for accounts and sessions
- Supabase Postgres for profiles, projects, memberships, and invitations
- Supabase Row Level Security for authorization
- Expo SecureStore for persisted mobile sessions

## Step 1: Install Dependencies

Open a terminal in the project directory:

```powershell
cd C:\personal\theprojecthuku
npm.cmd install
```

The project requires these Phase 1 packages:

- `@supabase/supabase-js`
- `expo-secure-store`
- `react-native-url-polyfill`

If PowerShell blocks `npm`, use `npm.cmd` as shown above.

## Step 2: Create a Supabase Project

1. Open the Supabase Dashboard.
2. Sign in or create a Supabase account.
3. Select **New project**.
4. Choose the organization where the project should live.
5. Set the project name, for example `the-project-huku-dev`.
6. Generate and store a strong database password.
7. Choose a region close to the primary users.
8. Create the project and wait until its database is ready.

Use a separate Supabase project for production. Do not use the production project while developing migrations or testing destructive changes.

## Step 3: Copy the Supabase Credentials

In the Supabase Dashboard:

1. Open **Project Settings**.
2. Open **API**.
3. Copy the **Project URL**.
4. Copy the **Publishable key** or legacy **anon public key**.
5. Do not copy the `service_role` key into the app.

From the repository root, create a local `.env` file from the template:

```powershell
Copy-Item .env.example .env
```

Open `.env` and replace the placeholders:

```env
EXPO_PUBLIC_SUPABASE_URL=https://your-real-project.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=your-real-anon-or-publishable-key
```

The `.env` file is ignored by Git. Only `.env.example` should be committed.

For this Expo app, use the `EXPO_PUBLIC_` names exactly. `NEXT_PUBLIC_` variables are commonly used by Next.js web apps and may not be injected into an Expo mobile bundle.

## Step 3b: Configure Email Redirect URLs

In Supabase, open **Authentication > URL Configuration** and add the callback URL for the environment you are testing.

Common examples:

```text
hukuproj://auth/callback
http://localhost:8081/auth/callback
http://localhost:19006/auth/callback
```

For web, use the exact host and port shown by Expo. Do not add only `http://localhost:3000` unless Expo is actually running on port 3000. The redirect URL must match the URL generated by the app.

## Step 4: Apply the Database Migration

The migration is located at:

```text
supabase/migrations/001_phase1_foundation.sql
```

Also apply the follow-up security migration:

```text
supabase/migrations/002_secure_project_creation.sql
```

For project invitations, also apply:

```text
supabase/migrations/003_project_invitations_acceptance.sql
```

If the invitation RPC reports `gen_random_bytes(integer) does not exist`, apply this corrective migration afterward:

```text
supabase/migrations/004_fix_pgcrypto_search_path.sql
```

For invitations to appear automatically on the recipient's projects page, apply:

```text
supabase/migrations/005_phone_invitation_inbox.sql
```

The recipient must have the same WhatsApp number in their profile as the number entered by the inviter. Formatting differences such as spaces, `+`, and punctuation are ignored.

If invitation acceptance reports `project_id is ambiguous`, apply this corrective migration after migration 005:

```text
supabase/migrations/006_fix_ambiguous_invitation_acceptance.sql
```

### Recommended method: Supabase SQL Editor

1. Open the Supabase Dashboard.
2. Select the development project.
3. Open **SQL Editor**.
4. Select **New query**.
5. Open `supabase/migrations/001_phase1_foundation.sql` in VS Code.
6. Copy the complete file contents.
7. Paste the SQL into the Supabase query editor.
8. Select **Run**.
9. Confirm that the query completes without errors.

The migration creates:

- `profiles`
- `projects`
- `project_members`
- `project_invitations`
- New-user profile trigger
- Project-owner membership trigger
- Project membership helper functions
- Invitation creation RPC
- Row Level Security policies
- Secure authenticated project-creation RPC
- Secure single-use project-invitation acceptance RPC

### Verify the migration

In the Supabase SQL Editor, run:

```sql
select table_name
from information_schema.tables
where table_schema = 'public'
  and table_name in ('profiles', 'projects', 'project_members', 'project_invitations')
order by table_name;
```

You should see four rows.

Then verify RLS:

```sql
select tablename, rowsecurity
from pg_tables
where schemaname = 'public'
  and tablename in ('profiles', 'projects', 'project_members', 'project_invitations')
order by tablename;
```

Each table should show `rowsecurity = true`.

## Step 5: Configure Email Authentication

The app uses email and password authentication.

For development:

1. Open **Authentication** in the Supabase Dashboard.
2. Open **Providers**.
3. Open **Email**.
4. Ensure email/password sign-in is enabled.
5. Decide whether **Confirm email** should be enabled.
6. In **URL Configuration**, add the callback URL from Step 3b.

### Option A: Confirm email enabled

This is safer and recommended for production.

- A user signs up.
- Supabase sends a confirmation email.
- The user confirms the email.
- The user returns to the app and signs in.

For local testing, configure the email templates and redirect URL if required by your Supabase project.

### Option B: Confirm email disabled

This is faster for early development.

- New users can sign in immediately after registration.
- It is less suitable for production because email ownership is not confirmed.

Use the setting deliberately and document which mode is active in each environment.

## Step 7: Test Account Creation

1. Open the app.
2. Confirm that the authentication screen appears.
3. Select **Create a profile**.
4. Enter:
   - Full name
   - Optional WhatsApp number
   - Email
   - Password
5. Select **Create profile**.
6. Complete email confirmation if it is enabled.
7. Sign in with the new account.

Verify the profile was created in Supabase:

```sql
select id, full_name, whatsapp_number, created_at
from public.profiles
order by created_at desc
limit 5;
```

Do not edit `auth.users` manually. The database trigger creates the matching `profiles` row.

## Step 8: Test Project Creation

1. After sign-in, confirm that **Your Projects** appears.
2. Enter a project name, for example `Huku Farm 2026`.
3. Select **Create project**.
4. Confirm the project appears in the list.
5. Confirm the role displays as `owner`.
6. Select **Sign out**.
7. Sign back in and confirm the project remains listed.

Verify the project and owner membership:

```sql
select
  p.name,
  p.owner_id,
  pm.user_id,
  pm.role,
  pm.status
from public.projects p
join public.project_members pm on pm.project_id = p.id
order by p.created_at desc;
```

The owner should have an active `owner` membership.

## Step 9: Verify Authorization

Use two separate test accounts.

### Test account A

1. Create a project while signed in as account A.
2. Record the project ID from the Supabase dashboard or SQL query.

### Test account B

1. Sign in as account B.
2. Confirm account B does not see account A's project.
3. Confirm account B cannot read account A's project through the app.

This verifies that the project membership policy is active. Do not skip this test before adding project data in later phases.

## Step 10: Check Environment Safety

Run these checks before committing:

```powershell
git status --short
Get-Content .gitignore
```

Confirm:

- `.env` is not listed as a file to commit.
- `.env.example` remains tracked.
- No `service_role` key appears in source files.
- No real Supabase key is written into `app.json`, JavaScript, TypeScript, or SQL files.

If `.env` was accidentally committed, rotate the exposed Supabase key immediately and remove the file from Git history using your normal repository security process.

## Troubleshooting

### The app says online features are unavailable

Check:

1. `.env` exists in the repository root.
2. Variable names exactly match:

```env
EXPO_PUBLIC_SUPABASE_URL=...
EXPO_PUBLIC_SUPABASE_ANON_KEY=...
```

3. The Expo process was restarted after creating or changing `.env`.
4. The URL begins with `https://`.
5. The Supabase project is running.

### Sign-up fails with a database error

Check:

1. The migration ran successfully.
2. The `profiles` table exists.
3. The `on_auth_user_created` trigger exists.
4. Email/password authentication is enabled.
5. The Supabase Auth logs contain the exact error.

### Project creation fails

Check:

1. The user is authenticated.
2. A matching row exists in `public.profiles`.
3. The projects insert RLS policy exists.
4. The `on_project_created` trigger exists.
5. The authenticated user is used as `owner_id` by the app.

### The project is created but does not appear

Check:

1. The owner membership trigger ran.
2. The membership status is `active`.
3. The project-list query is being made with the same signed-in user.
4. The `project_members` and `projects` select policies exist.
